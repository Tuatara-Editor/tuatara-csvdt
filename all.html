csvdt Manual

for Tuatara 0.90.40 and later, every chapter on one page

This manual is written with modal editing on, first and foremost. Where a command also has a key that works with modal editing off, it is given as well, as the non-modal key.

What the csvdt package is

The package that runs the csvdt program over the records of a CSV buffer.

csvdt converts the timestamps and durations in the records of a CSV file. The package hands it the buffer, in the background, and shows what csvdt writes in a buffer of its own, *csvdt output*. The buffer is never changed.

csvdt is a program of its own, installed apart from Tuatara. The package needs csvdt 1.2.0 or later, which takes a selection itself; an older one is refused with a message saying so. Its options and what they do are in its own help; C-c v h shows it. This manual covers what the package adds: which lines a run covers, how the arguments are typed, and what happens to the result.

1.1 The keys

In a CSV or TSV (tab-separated values) buffer, the keys are under C-c v. Tuatara labels the prefix csvdt in its key help.

KeyCommandWhat it runs csvdt over
C-c v rcsvdt-run-dwimbanked lines and selection, else all
C-c v bcsvdt-run-bufferthe whole buffer
C-c v SPCcsvdt-run-regionthe selection
C-c v kcsvdt-run-bankedthe banked lines
C-c v ?csvdt-describe-runnothing: says what a run would cover

C-c v vcsvdt-versionnothing: says which csvdt runs

In any other buffer the commands are run with M-x, or from a key of your own in the init file:

(bind-key "; c" 'csvdt-run-dwim :map :leader)   ; SPC ; c

1.2 If csvdt is not found

M-x check-health says whether Tuatara finds csvdt. When it does not, chapter 5 says how to name its path. C-c v v says which csvdt runs; the version is asked once for each program found, not at each run.

What gets processed

Which lines a run covers, and what csvdt takes of them.

csvdt-run-dwim takes the banked lines and the selection together, merged so a line in both goes once. With neither, it takes the whole buffer.

Banked lines are Tuatara's own (bank-lines, m l in normal state). csvdt writes them in buffer order, whatever order they were banked in. Running over them leaves them banked.

The selection is taken as y and d take it: a line selection whole, a rectangle by the rows it spans. A rectangle's columns are ignored, because picking columns is csvdt's job (--remove, -a). A run takes the main selection only, not the places of several cursors or of a split.

csvdt-describe-run says what a run would cover, without running it. It has no line of arguments to read. It counts whole lines, as they go to csvdt, and says nothing of the widening csvdt does to reach whole records.

2.1 What csvdt is given

csvdt is given the whole buffer, or the part it is narrowed to, as its input file. A run over the whole buffer says nothing more. A run over banked lines or a selection adds --lines with the lines picked, counted from 1 at the start of the input, as in --lines 3-5,9,20-22. csvdt reads the input as it reads any file and keeps every record that touches a selected line, whole, in input order, each once. The output is what a run over the whole buffer writes for those records. The package reads nothing of the text as CSV.

So csvdt decides where a record begins, which lines are comments (--comment) and which record is the header. Under -H -p the header is the buffer's first record and is printed once at the top, whether or not it was selected. With a selection or banked lines, a duration (-d with one column) is measured from the row before the first one taken, taken or not.

  • A selection that starts or ends inside a line takes the whole line. The run says , selection widened to whole lines.
  • A quoted field can hold a line end, so a record is not always a line. When csvdt takes lines the selection did not name, the run says , widened to whole records: lines 2-3, naming every line it took.
  • A narrowing that begins or ends inside a line hands csvdt that line in part. The run says , first line cut short by the narrowing (or the last, or both). A narrowing that cuts a quoted field at a line end is csvdt's to report.
  • A selection of only comment or blank lines gives an empty result, and csvdt says so.

2.2 The bytes

The buffer's bytes go to csvdt as they are. A file that is not UTF-8 reaches csvdt as it is on disk, and csvdt refuses it in its own words. Line ends are sent as \n when the buffer's are \r\n.

Arguments

The line of csvdt options a run asks for.

A run asks for csvdt's arguments in the minibuffer, as a line the way a shell takes one. The line starts as *csvdt-default-arguments*, which is -H -p, and is left selected. C-c v v says which csvdt will run. Its options are asked for in the background while you type, for completion.

KeyWhat it does
type anythingreplaces the prefill
RIGHT or C-fkeeps it, to add to
RETruns it as it stands
TABcompletes the option before the cursor
M-p and M-nback and forth through lines run before

The prefill is selected, not only offered, because leaving -H off a file with a header is loud, while passing it to a file without one is quiet. The first row is then taken for a header and goes through unconverted.

3.1 How the line is split

The line is split as a shell splits it, and not on commas, because a comma is csvdt's own separator inside a value (-a 1,0, -i 0,replace). Either kind of quote works.

  • Double quotes take \t, \n, \r, \\ and \". Any other backslash is refused, so "C:\data" is refused rather than misread.
  • Single quotes take everything as it is.
  • Outside quotes a backslash is itself.

Nothing is run through a shell.

3.2 File names

A file name in the line is refused. These commands give csvdt the lines on its standard input, and a named file would take their place in a result that looks exactly like a run over them.

Only a name that is a file on disk is refused. Which arguments are values and which are file names comes from csvdt --list-options, so -u 0 with a file called 0 lying about is still a run.

3.3 What csvdt reports

The help is csvdt's own --help, read from the program each time. The options offered for completion come from csvdt --list-options. The package keeps them against the program's real path and the time it was written, so a rebuilt csvdt is asked again and an unchanged one is not run just to find that out. A csvdt too old to list its options has them read from --help instead.

Nothing in the package needs updating when csvdt changes. Only one option is named, --lines, which tells csvdt which lines a run over part of a buffer means. The tests hold it to an option csvdt still reports, and fail if any other option csvdt reports is named in the package.

Running, and the output

What happens while csvdt runs, and where the result goes.

4.1 A run is a job

A quick run looks instant. One that takes more than half a second carries on in the background with the editor free. The letter P is lit in the mode line, C-x j lists the job, and C-x J (M-x stop-job) ends csvdt. A second run over the same buffer while one is going is refused, not queued.

csvdt runs shut in by the sandbox (bwrap): it reads the lines on its standard input and sees the system's programs and libraries, and itself, read only, and nothing else of yours. Without the sandbox it does not run, and the echo area says why.

4.2 The output buffer

The output goes to *csvdt output*, in the major mode *csvdt-output-mode* names, csv-mode by default. When that mode cannot be entered the buffer is left in fundamental-mode, so a result csvdt has made is not lost.

The buffer is one to edit. Sort its lines, or run csvdt on it again to feed a result back through. Lines banked in the previous result are let go, because the text they stood for is gone.

4.3 How much csvdt may write

What csvdt writes is held in the editor's memory until it is in the buffer, so a run may write at most *csvdt-output-multiple* times its input, eight by default, and never less than 64 MB. Whatever those say, it may never write more than a quarter of the editor's free memory as the run starts. Most runs write about as much as they read. Some options write far more: -f=widest pads every record to the widest one, so a file with one very wide record and many short ones grows many times over. A run that writes more than its limit is ended, nothing of it is shown, and the echo area says so:

csvdt was ended: it wrote more than 64.0 MB, 8 times its input (*csvdt-output-multiple*) or 64.0 MB at least, and no more than a quarter of the memory free; nothing is shown

Raise *csvdt-output-multiple* for such a run when the computer has the memory for it (chapter 5). The quarter of free memory is not a setting: a run that reaches it would leave the editor too little to go on.

4.4 The echo area

The source buffer is never changed. On success the echo area gives the line count, the stretches when there was more than one, the widening notes of chapter 2, and anything csvdt said on stderr about a run that still succeeded:

csvdt -H -p -u0 -i 0,replace: 3 lines from 2 stretches

On failure it gives csvdt's own reason and how it ended. What csvdt wrote before failing is shown in *csvdt output*, except when the run was fed from that buffer, whose text is kept:

csvdt exited with an error: '--utc' was given "0-i", which is not a column number.

Settings and the csvdt program

The package's settings, and how to point it at a csvdt that is not on the PATH.

Each setting has its help in C-h v. Chapter 6 lists them with their defaults. Set them in the init file, after :config of load-package.

5.1 The csvdt program

*csvdt-program* is a name, looked for on the PATH, or a full path from / or ~. A full path is the file that is run, and it is never looked for on the PATH. A relative path such as "./target/release/csvdt" is refused, because it would run whatever file of that name stands beside the CSV file.

(load-package "csvdt" :source "https://github.com/Tuatara-Editor/tuatara-csvdt"
  :config
  (setf *csvdt-program* "~/src/csvdt/target/release/csvdt"))

5.2 The arguments

*csvdt-default-arguments* is the text the argument line starts with. The default, -H -p, suits a file with a header row, the header printed. Use "" for none.

5.3 Obsolete settings

Five settings fed the package's own reading of the buffer as CSV, which csvdt now does itself (chapter 2). They are obsolete: they do nothing, and are removed in the next major version. Setting one is harmless.

  • *csvdt-region-carries-header*: whether the buffer's header went in front of a selection. csvdt always takes the buffer's first record for the header now.
  • *csvdt-header-options*, *csvdt-single-quote-options*, *csvdt-read-delimiter-options* and *csvdt-comment-options*: the names of the options saying the first record is a header, making ' the quote character, setting the delimiter fields are read with, and naming a comment character. A run over part of a buffer under =--comment is no longer refused.

5.4 The output mode

*csvdt-output-mode* is the major mode of *csvdt output*. See chapter 4.

5.5 How much csvdt may write

*csvdt-output-multiple* is how much csvdt may write for a run, as a multiple of its input: 8 by default, and never less than 64 MB, nor more than a quarter of the editor's free memory. A run that writes more is ended. See chapter 4.

(load-package "csvdt" :source "https://github.com/Tuatara-Editor/tuatara-csvdt"
  :config
  (setf *csvdt-output-multiple* 32))

5.6 Tests

tools/test.sh in the package runs its tests. The runs of csvdt need a program to run: CSVDT=/path/to/csvdt names it, else the one on the PATH is used. Without one those tests are skipped, not passed.

Every command and setting

Each command and setting of the csvdt package, to look one up by name.

The tables are made from the program each time this manual is made, so they never list a command or setting that the package does not have. The first table has four columns. The first two are keys: the modal keys, which work only with modal editing on, and the non-modal keys, which work with it off too. A command with no key says M-x and its name in the second column, because you can only run it by its name. The third column is the name of the command and the fourth says what it does.

To run a command by its name, press M-x, type a few letters of the name and press RET. To find a command from within the editor, press C-h f. To find the command that a key runs, press C-h k and then the key. The editor's own settings and commands are in chapters 21 and 22 of its manual.
