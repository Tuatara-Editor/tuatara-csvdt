Running, and the output

What happens while csvdt runs, and where the result goes.

4.1 A run is a job

A quick run looks instant. One that takes more than half a second carries on in the background with the editor free. The letter P is lit in the mode line, C-x j lists the job, and C-x J (M-x stop-job) ends csvdt. A second run over the same buffer while one is going is refused, not queued.

4.2 The output buffer

The output goes to *csvdt output*, in the major mode *csvdt-output-mode* names, csv-mode by default. When that mode cannot be entered the buffer is left in fundamental-mode, so a result csvdt has made is not lost.

The buffer is one to edit. Sort its lines, or run csvdt on it again to feed a result back through. Lines banked in the previous result are let go, because the text they stood for is gone.

4.3 The echo area

The source buffer is never changed. On success the echo area gives the line count, the stretches when there was more than one, the widening notes of chapter 2, and anything csvdt said on stderr about a run that still succeeded:

csvdt -H -p -u0 -i 0,replace: 3 lines from 2 stretches

On failure it gives csvdt's own reason and exit status. What csvdt wrote before failing is shown in *csvdt output*, except when the run was fed from that buffer, whose text is kept:

csvdt exited 100: '--utc' was given "0-i", which is not a column number.
